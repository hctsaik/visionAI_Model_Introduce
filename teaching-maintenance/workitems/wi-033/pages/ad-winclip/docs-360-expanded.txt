為什麼需要這個設計？

人工組合正常／異常狀態詞與句型，固定 CLIP 把文字和視窗影像轉成可比較的表示。各視窗的異常分數排回覆蓋位置，以調和平均聚合重疊與多尺度線索。WinCLIP+ 再用少量正常品建立 patch／視窗特徵庫，找最相似正常特徵的距離，融合文字線索。

模型專屬因果鏈

實作時逐步核對

主圖已在上方第一遍。這裡只核對每一步要鎖定的設定與為什麼，不再重貼同一張圖。

1
鎖定文字側：class name、state words和prompt ensemble

固定CLIP/text encoder、tokenizer、產品類別命名、normal/anomaly state vocabulary、templates、ensemble weights、text embedding normalization與cache revision。

因為：文字側不是說明文案而是模型輸入；一個詞、模板或tokenizer改變即可移動similarity margin。

設定核對：工程圖核對：state words/templates → normal/anomaly text embeddings

2
鎖定視覺側：ROI全圖、windows與patch layout

固定ROI/registration、resize/crop/padding、full-image/window/patch extraction、sizes/strides/overlap/scales與selected CLIP features。

因為：每個window決定模型實際看見的有效像素與情境；改layout就改特徵、成本與小缺陷可見性。

設定核對：工程圖核對：ROI → image / windows / patches

3
比較normal與anomaly文字相似度

frozen CLIP image embeddings 分別與兩個text ensembles算normalized similarities；WinCLIP+另按鎖定policy加入few-normal reference contribution。

因為：candidate來自相對margin，不是CLIP自然語言的自信；normal reference雖可補資訊，也帶來contamination、coverage、memory和latency依賴。

設定核對：工程圖核對：visual embeddings → similarity margins (+ references)

4
融合、校正與abstain後才輸出候選

image/window/patch margins依固定weights、map resize/smoothing/mask、aggregation、local calibration、threshold與abstain/review rule形成candidate。

因為：不同尺度的margin不能靠視覺色彩比較；融合與校正可改低FPR，prompt score也不會自行轉成release decision。

設定核對：工程圖核對：margin fusion → calibration → review gate

失效案例、選型與小規模試做

什麼情況不能相信它？

這一區保留完整工程條件，供準備實作或驗收的人逐項核對。

prompt wording、state words、class names、tokenizer或text embedding normalization改變

可能看到：normal/anomaly margin可反轉；舊threshold與舊結果失去可比性。

正確下一步：HOLD；保存prompt/cache revision，重做prompt sensitivity、local calibration、target holdout和regression。

window/patch尺度、stride、padding或aggregation不適合tiny defect

可能看到：缺陷可能落在window邊界、被背景稀釋或在插值/平滑後消失。

正確下一步：量effective pixels、window count/成本、small-defect evidence和low-FPR；無證據時不要宣稱localization。

WinCLIP+ reference bank未治理，或image/text domain/naming gap和global logic存在

可能看到：contamination或coverage問題改變margin，產品名稱和視覺domain不合也會誤判；關係型錯誤仍可能未見。

正確下一步：保存reference IDs/selection/contamination audit；檢查domain/naming transfer，必要時HOLD或用specialist path。

輸入與版本：先看文字與視窗怎麼對齊，再看 WinCLIP+ 的正常參考。；關鍵機制：人工組合正常／異常狀態詞與句型，固定 CLIP 把文字和視窗影像轉成可比較的表示。各視窗的異常分數排回覆蓋位置，以調和平均聚合重疊與多尺度線索。WinCLIP+ 再用少量正常品建立 patch／視窗特徵庫，找最相似正常特徵的距離，融合文字線索。；獨立驗證：量 prompt/naming variance、small-defect effective pixels、low-FPR escape、false reject、review load、reference benefit、P95/P99 與 drift。；失敗處理：看不清細節先改善取像；位置或文字矛盾就回原圖覆核。
