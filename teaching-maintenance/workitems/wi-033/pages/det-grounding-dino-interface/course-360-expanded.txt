失效案例、選型與小規模試做

什麼情況不能相信它？

這一區保留完整工程條件，供準備實作或驗收的人逐項核對。

phrase ambiguity、domain vocabulary gap、同義詞/tokenization/prompt drift

可能看到：query/score space 改變，candidate boxes 可能移位、消失或新增，zero-shot score 不可跨 prompt 直接比較。

正確下一步：固定並保存 vocabulary/template/tokenization，量 seen/unseen grounding recall、prompt sensitivity、specialist confirmation rate 和 P95。

tiny object、false localization、ROI inverse mapping 或 threshold/NMS 未鎖

可能看到：phrase 候選可能框錯位置、漏掉小目標或無法回到 raw image 供專業檢查。

正確下一步：鎖 pixels/ROI/threshold/NMS/coordinate transform，量 grounding recall/IoU、failure images 和 inverse-map 可追溯性。

把 phrase box 直接視為 defect truth、metrology 或 release

可能看到：跳過 prompt bias、語意不確定、局部驗證與產品證據，造成高信心危險誤用。

正確下一步：禁止直接 release；candidate 必須 inverse map 後交 detector/AD/人工 specialist，保留 confirmation result。

工程第一步

POC 第一件事：把 phrase 到專家確認的證據鏈完整記下來
鎖 raw AOI/ROI、prompt vocabulary/template/version、tokenization、text/image preprocessing、phrase/box threshold、NMS、coordinate transform、specialist owner 與不得 release 的政策。

目前做法

以固定 raw AOI/ROI、prompt vocabulary/template/tokenization、text/image preprocessing、phrase/box thresholds、NMS、inverse map 和 specialist route 的 candidate workflow 為 baseline。

要量什麼

按 seen/unseen terms、synonyms、tiny/false-localization、domain vocabulary、product/recipe split 分層量 grounding recall/IoU、prompt sensitivity、inverse-map success、specialist confirmation rate、embedding/forward/postprocess P95。

反例測試

同一 AOI 僅替換相近 phrase 或 tokenization，保留不同高分 boxes；預期 score 不可跨 prompt 當 defect probability，必須保存 prompt bundle 並交 specialist confirmation。

誰確認

由工程 vocabulary owner 管 phrase/template revision；CV/VLM owner 簽核 grounding/prompt evidence，具名 detector/AD/人工 specialist owner 判定 defect，release owner 保有最終權限。

先停下來的訊號：prompt/ROI/threshold/inverse-map 未版本化、詞彙敏感度或 tiny/localization 未通過、specialist owner 不明，或有人想由 phrase box 直接 release 時，先 HOLD。
