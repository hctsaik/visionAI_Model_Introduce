為什麼需要這個設計？

多類正常影像共訓重建模型，骨幹固定。UniAD 在注意力中遮住自己與近鄰，配合逐層查詢與訓練時特徵擾動，減少從輸入直接複製；推論比較原始與重建特徵，將差異排回位置圖。

模型專屬因果鏈

實作時逐步核對

主圖已在上方第一遍。這裡只核對每一步要鎖定的設定與為什麼，不再重貼同一張圖。

1
把各類 ROI 轉成共享的多層 feature

多類別 clean normal ROI 經固定 backbone、selected maps、ROI/transform，形成 layer features；保留 category IDs與coverage。

因為：共享特徵空間若被大宗類別主導，稀有類別可能沒有可重建的正常表示。

設定核對：工程圖核對：class ROI → multi-layer backbone features

2
用 jitter 與 neighbor mask 限制 copy

訓練時在 feature 加 jitter，layer-wise queries 經 masked decoder 重建 feature，遮住不應直接讀取的鄰近資訊。

因為：純重建容易把異常 feature 原樣傳遞；控制使模型必須依更廣的正常規律預測局部。

設定核對：工程圖核對：feature jitter + queries + neighbor mask

3
每層量原 feature 與重建 feature 的差距

測試 feature 經同一 query/mask path，依固定 distance 得到每層 local residual map。

因為：高 residual 表示這條受控共享路徑無法復原局部，不等於缺陷類別或產品放行結論。

設定核對：工程圖核對：layer-wise reconstruction residual

4
融合後仍以每個 category 做 review

各層 map 經 resize、fusion、aggregation、threshold 形成候選，並按每類保存 low-FPR、review load 和 future/drift evidence。

因為：共享模型的平均表現可掩蓋罕見產品的分數尾端；每類的 operating point 不能由 pooled result 代替。

設定核對：工程圖核對：layer fusion → per-category gate

什麼情況不能相信它？

這一區保留完整工程條件，供準備實作或驗收的人逐項核對。

neighbor mask/jitter 太弱，模型走 identity shortcut

可能看到：異常 feature 可被近鄰或輸入捷徑重建，residual 變小，造成 escape。

正確下一步：HOLD；做 mask/jitter ablation，檢查真實 escaped defects，不用訓練 loss 取代。

mask/jitter 太強、normal modes 不足或稀有類別被壓縮

可能看到：合法正常 feature 也無法復原，特定類別 false reject 高。

正確下一步：按 category、lot、view 分層驗每類 support、threshold、review load 和 future split。

tiny defect、ROI/drift 或 global logical anomaly

可能看到：feature stride 或後處理可能抹掉小訊號；共享重建也未必表達缺件與關係。

正確下一步：驗 effective pixels/acquisition state；改用合適的結構或規則 path，條件不成立先 HOLD。
