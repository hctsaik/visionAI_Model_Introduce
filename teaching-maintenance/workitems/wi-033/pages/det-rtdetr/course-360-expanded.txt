為什麼需要這個設計？

原版 RT-DETR 將高層特徵的尺度內注意力，與卷積式跨尺度融合分開；細、中尺度直接參與融合。由編碼特徵選較好的查詢起點，解碼器再取影像線索逐步修正框。圖中 q1/q2 對應 A/B，灰色 q3 未選入輸出；數量與結果只是示意。

看解釋與可接受的取捨

固定資料、硬體與漏件容許量，比不同解碼深度、取像條件和 YOLO 基準的漏件、重複、端到端延遲及人工覆核。恢復層數可能省去返工，但提高解析度會增加運算；不能只以無 NMS 判定較快。兩者皆需要類別框標註，換產品需核對重訓與門檻；要輪廓則另選分割能力。

query：模型挑出來、值得仔細看的少量位置
P95：20 次中最慢一次約多久完成
RT-DETR：直接學一組物件，並降低計算負擔

Dense框通常要整理重複；DETR以集合預測減少對NMS的依賴，但全尺度Transformer計算昂貴。RT-DETR把尺度內互動和跨尺度融合分開，並選較好的初始queries，讓集合式偵測更適合即時工作。

高效編碼，分開兩種資訊交換

Hybrid encoder在高層特徵做尺度內注意力，再用卷積式跨尺度融合傳遞細節與脈絡，避免在所有細格上做昂貴互動。省哪一段必須說清楚，不能只因叫real-time就保證本站節拍。

因為：Dense框通常要整理重複；DETR以集合預測減少對NMS的依賴，但全尺度Transformer計算昂貴。RT-DETR把尺度內互動和跨尺度融合分開，並選較好的初始queries，讓集合式偵測更適合即時工作。

什麼情況不能相信它？

這一區保留完整工程條件，供準備實作或驗收的人逐項核對。

small object 欠採樣、query capacity 不足或密集重疊

可能看到：可用 queries 可能不夠或 features 不含訊號，造成 miss/錯類；set output 不代表所有物件都已被覆蓋。

正確下一步：先驗 effective pixels、query count/selection、size-bin/overlap recall 和 output capacity；gate 不通過則 HOLD。

decoder depth、export operators/fusion、precision、batch 或 postprocess 改變

可能看到：recall、VRAM、latency、數值輸出和 camera-to-PLC P95 都可能變，論文 FPS 無法外推。

正確下一步：把每個 depth/export/runtime 當成獨立 operating point，保存 graph/operators，量 end-to-end P95 與 failure cases。

labels/ignore zones、domain/taxonomy/OOD 或 decision policy 改變

可能看到：closed-set boxes 可能高分但不代表未知檢出或可靠製程決策。

正確下一步：以共同 split、calibration、false HOLD、OOD/review 和 owner action gate，不因「real-time」或 box score 直接 release。

相鄰方法比較

不要比名稱；比 query set 如何形成
RT-DETR
依據：hybrid encoder 融合的多尺度 features、selected object queries/reference points 與 set labels
可用輸出：指定 decoder depth 的 class/box set，經完整 runtime/P95/recall gate
YOLO dense detector
依據：多尺度 feature locations 的 dense box/class/objectness candidates
可用輸出：decode/NMS 後 boxes；不是 query set，也需 size/overlap/P95 驗證
DINO detector
依據：multi-scale encoded features、mixed queries/reference boxes 和 supervised set matching
可用輸出：iterative refined boxes/classes；training denoising groups 不進 production inference

工程第一步

POC 第一件事：把每個 decoder depth 當成不同產品候選
鎖 implementation/variant/weights、backbone/hybrid encoder、query count/selection、decoder layers、input/padding、matching/loss、precision/export/engine、batch、postprocess、labels/ignore 和 decision policy。
針對每個 depth/export/hardware，以 critical-size、overlap、ROI/product、lot/recipe/OOD split 保存 box sets、false alarms/HOLD、VRAM、operators 和整條相機到決策時間。
比較 critical recall、overlap misses、calibration、false HOLD、camera-to-PLC P95、VRAM、throughput 和 review load；不合格的 depth 不因 forward 快而採用。
目前做法

以固定 labels/ignore、effective pixels、query count/selection、decoder depth、export/hardware、postprocess 和人工 ROI review 的 RT-DETR operating point 為 baseline。

要量什麼

把每個 decoder depth × export × hardware 當獨立 operating point，按 small/overlap/product/lot/recipe/OOD 分層量 critical recall、overlap miss、false HOLD、calibration、VRAM、camera-to-PLC P95、review load。

反例測試

將 decoder 改淺或替換 export engine，只報 forward FPS；預期即使 FPS 提升，也不能代替 small/overlap recall 和完整 P95，未實測即 HOLD。

誰確認

由產線／SLA owner 定義 camera-to-PLC 需求；CV owner 簽核 query/depth/export evidence，品質 owner 管 false HOLD/review，製程 owner 批准採用的 operating point。

先停下來的訊號：pixel/query capacity不足、depth/export stack 未實測、small/overlap/OOD gate 不足、或 P95 沒涵蓋整條 camera-to-decision 路徑時，先 HOLD/REVIEW。
