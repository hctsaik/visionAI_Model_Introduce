實作時逐步核對

主圖已在上方第一遍。這裡只核對每一步要鎖定的設定與為什麼，不再重貼同一張圖。

1
先鎖定重建 target 與輸入 recipe

選 image x 或 feature F 作為 target，固定 ROI、resize、mask、normalization、augmentation 與 support IDs。

因為：pixel residual 對照明與對位敏感；feature residual 可能忽略細節。兩者的分數不能無條件混用。

設定核對：工程圖核對：target x／F 與 input contract

2
讓 encoder 把正常訊號壓成 latent

encoder 將正常 target 轉成 latent z；latent dimension、skip connections 與 architecture 都以版本保存。

因為：容量決定哪些正常變化能通過，也決定模型是否會把不該重建的異常一起帶過去。

設定核對：工程圖核對：encoder → latent z

3
decoder 只從正常路徑重建 target

decoder 由 z 產生 x-hat 或 F-hat，以鎖定 L1/L2、SSIM 或 feature loss 只對正常 support 訓練。

因為：loss、mask 與 normal coverage 決定『重建得好』的定義；不是任何視覺上平滑的結果都可靠。

設定核對：工程圖核對：decoder → reconstruction

4
把 residual 變成候選 evidence

測試 target 與 reconstruction 依已鎖定 residual、smoothing、mask、aggregation 和 threshold 形成 map 與 image candidate score。

因為：同時看 input、reconstruction、residual 才能辨別刮痕、正常 blur 與取像偏移；分數本身不是 release probability。

設定核對：工程圖核對：residual map → aggregation → review

bottleneck 太弱、normal coverage 不足或輸入 blur

可能看到：正常品也重建不好，residual 增加，造成 false HOLD。

正確下一步：分層檢查 lot/view/light 的 input、reconstruction、residual；以隔離正常 holdout 調整容量與 recipe。

容量太強、skip 太直接或 support 受污染

可能看到：異常可被重建，或污染模式被當作正常，殘差變小而漏檢。

正確下一步：HOLD；檢查 escaped defects、contamination audit、latent／skip 設定，重訓後做 real challenge qualification。

ROI／照明／對位漂移或目標是 logical anomaly

可能看到：pixel residual 可能被量測條件主導；缺件、錯件與關係規則未必會形成局部重建差。

正確下一步：先查 acquisition state；對 logical anomaly 改採能檢查存在、位置或結構規則的方法。
