失效案例、選型與小規模試做

什麼情況不能相信它？

這一區保留完整工程條件，供準備實作或驗收的人逐項核對。

prompt drift、text template/vocabulary 改變或 visual exemplar bias

可能看到：prompt representation 改變，候選 boxes/masks/scores 可能偏向不同外觀或失去穩定性。

正確下一步：版本化 prompt source/IDs/embeddings，分開量 text/visual、seen/unseen recall、prompt stability 和 specialist confirmation。

detection/segmentation mode 混用，或 threshold、NMS、mask postprocess、inverse mapping 未鎖

可能看到：box、mask、score 被錯當成同一粒度，邊界/定位差異無法重播，mask inconsistency 被隱藏。

正確下一步：每個 mode 有自己的 head/postprocess/ROI/metrics contract；量 box recall、mask consistency、tiny/localization errors 和 P95。

把 text/visual prompt candidate 視為製程證據、defect truth 或 release

可能看到：小物、prompt/exemplar 偏差、mask 不一致和語意不確定被跳過，造成高風險錯誤決策。

正確下一步：只允許 candidate-to-specialist workflow；保存 raw image、prompt/mode、outputs、postprocess/inverse ROI 和 review result。

工程第一步

POC 第一件事：把每種 prompt source × mode 視為獨立候選流程
鎖 exact version、raw AOI/ROI/pixels、text templates/vocabulary、visual exemplar IDs、prompt embeddings/preprocess、detection/segmentation mode/head、threshold、NMS/mask postprocess、inverse map、export/runtime 和 specialist owner。
對 text/visual、seen/unseen、small/overlap、prompt drift/exemplar bias、mask inconsistency、product/recipe/OOD 分別建立 split，保存 outputs、candidate ROIs、confirmations、failure images 和 P95。
量 mode-wise candidate recall、box localization、mask consistency、prompt stability、embedding/forward/postprocess P95 和 review load；最終 defect/release 仍由 specialist evidence 決定。
目前做法

以固定 raw AOI/ROI/pixels、exact version、text template/vocabulary 或 visual exemplar IDs、prompt embeddings/preprocess、detection/segmentation mode、threshold、NMS/mask postprocess、inverse map 和 specialist workflow 為 baseline。

要量什麼

分 text/visual prompt、detection/segmentation mode、seen/unseen、small/overlap、prompt drift/exemplar bias、mask consistency、product/recipe/OOD 分層量 candidate recall、box localization、mask consistency、prompt stability、embedding/forward/postprocess P95、review load。

反例測試

換成不同光照或帶背景偏差的 visual exemplar，並切換 segmentation mode；預期候選／mask 可改變，精細 mask 不可自動作 physical boundary 或 release。

誰確認

由 prompt/exemplar owner 管 source/version；CV owner 簽核 mode-specific head/postprocess evidence，specialist owner 確認 raw evidence，release owner 持有最終動作權。

先停下來的訊號：prompt source/mode/postprocess 未鎖、text/visual 行為未分開驗、small/mask consistency/P95 不足、或 candidate 被要求直接變成製程決策時，先 HOLD。

讀完請自己講回來

YOLOE 的 visual prompt segmentation mask 看起來很精細。你可以把它當成缺陷的精確物理邊界並直接 release 嗎？
看本頁練習的核對說明

不可以。visual exemplar、mode、mask head、threshold、NMS/postprocess 和 inverse mapping 都會影響這個 candidate mask；它也不提供 calibration、repeatability 或 physical uncertainty。先分 mode 驗 mask consistency/邊界/小物行為，再交 specialist evidence 和 owner review。
