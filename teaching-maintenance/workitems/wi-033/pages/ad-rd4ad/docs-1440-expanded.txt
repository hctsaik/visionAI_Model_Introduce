模型專屬因果鏈

實作時逐步核對

主圖已在上方第一遍。這裡只核對每一步要鎖定的設定與為什麼，不再重貼同一張圖。

1
由 frozen teacher 取多尺度 normal feature

乾淨 normal ROI 依固定 recipe 經 frozen pretrained encoder，輸出選定層級的 teacher feature pyramid。

因為：教師 checkpoint、層級與 ROI recipe 決定模型看見哪些局部；domain mismatch 會讓正常與異常差異都失真。

設定核對：工程圖核對：frozen teacher → multi-scale features

2
讓一個 one-class bottleneck 學正常訊息

trainable bottleneck 與 reverse decoder 只用正常資料，將 teacher features 壓縮後以反向尺度順序重建。

因為：受限通道的目的，是保留正常結構而非逐點複製輸入；bottleneck 太窄會誤拒正常，太寬又可能吸收異常。

設定核對：工程圖核對：one-class bottleneck → reverse decoder

3
逐層比較教師與重建 feature

測試 ROI 同時走 teacher 與 normal-trained reverse path；每個對應位置計算 1−cosine(F_teacher,F_decoder) 的 discrepancy。

因為：RD4AD 的候選來自兩個 feature 表示不一致，而不是 input 與重建影像的像素差。

設定核對：工程圖核對：per-level cosine discrepancy

4
多尺度差異融合成候選，再 review

每層 discrepancy map resize 到共同 grid，依鎖定 addition、smoothing 與 max 等規則融合為 map 和 image candidate score。

因為：fusion、Gaussian smoothing 與 max aggregation 都能放大或稀釋小熱點；它們是 operating point 的一部分，不是純視覺裝飾。

設定核對：工程圖核對：resize → fusion → smoothing → gate

失效案例、選型與小規模試做

什麼情況不能相信它？

這一區保留完整工程條件，供準備實作或驗收的人逐項核對。

bottleneck 太受限或 normal modes 未涵蓋

可能看到：合法正常微特徵無法重建，discrepancy 大，false reject 與 review load 上升。

正確下一步：以隔離 holdout、不同 lot/view 支援抽樣和 seed spread 驗證，不要只壓低訓練 loss。

decoder 過度泛化或 support 受污染

可能看到：異常 feature 也可能被重建，或污染型態被教成 normal，造成小 discrepancy 與漏檢。

正確下一步：HOLD；審查 normal support、escaped defects 與容量設定，重新訓練後用真實 challenge qualification。

teacher domain mismatch、ROI／照明漂移或 tiny defect 被 smoothing 稀釋

可能看到：feature 差距反映量測或 feature stride，而非目標缺陷。

正確下一步：先查 acquisition／teacher fit／effective pixels；保存每層 map、resize、fusion、smoothing 與失敗例。

只有正常資料時，可比較 RD4AD 的特徵重建與 AE 的像素重建；能設計合成異常時，DRAEM 是另一候選。換產品需核對正常資料涵蓋、訓練適配與門檻；用相同未見正常和真缺陷、硬體與解析度一起比誤報、漏檢、時間及覆核成本。輸出都須經驗證，不直接當精確尺寸。
