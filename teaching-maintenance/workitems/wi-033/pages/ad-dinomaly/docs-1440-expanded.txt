模型專屬因果鏈

實作時逐步核對

主圖已在上方第一遍。這裡只核對每一步要鎖定的設定與為什麼，不再重貼同一張圖。

1
以固定 foundation encoder 產生多層 tokens

多類別 clean normal ROI 依固定 feature recipe 經選定 ViT layers，輸出 patch tokens 和其空間對應。

因為：checkpoint、layer、stride、ROI 和類別取樣決定 token 正常性；frozen backbone 只固定前段，不保證整個系統不學習。

設定核對：工程圖核對：ROI → selected foundation tokens

2
加入 anti-copy bottleneck 與 decoder controls

tokens 經 noisy／dropout bottleneck、linear attention 與 loose reconstruction 設計進入 trainable decoder，僅用 normal data 訓練。

因為：若路徑太容易逐 token copy，異常也會被重建；這些 controls 用來讓 residual 有機會代表超出正常規律的部分。

設定核對：工程圖核對：noise / linear attention / loose decoder

3
比較原 token 與重建 token

測試 tokens 與 decoder output 在選定 layer、位置與 distance rule 下比較，得到 token-wise residual maps。

因為：candidate 的來源是 token reconstruction discrepancy；它既不是 raw pixel error，也不等於模型知道異常的名稱。

設定核對：工程圖核對：token residual per layer

4
融合各層，保留每個類別的 evidence

各層 residual 經固定 resize、fusion、aggregation、calibration/threshold 形成 map 和 image candidate score，並按 category 保存結果。

因為：shared model 的 pooled result 可遮蔽稀有類別失敗；per-class low-FPR 和 review load 才能證明部署邊界。

設定核對：工程圖核對：layer fusion → per-class review gate

什麼情況不能相信它？

這一區保留完整工程條件，供準備實作或驗收的人逐項核對。

anti-copy controls 太弱或 decoder 過度重建

可能看到：異常 token 可能被原樣重建，residual 降低，造成 escape。

正確下一步：HOLD；做 controls ablation、查看真實 escaped defects，而非只用平均 reconstruction loss。

controls 太強、feature mismatch 或稀有類別 coverage 不足

可能看到：合法 normal token 也無法重建，false reject 對某些類別特別高。

正確下一步：以每類 support/future split、seed spread、teacher/domain fit 分層檢查，不能只報 pooled AUROC。

patch stride、ROI/drift 或 global logic

可能看到：tiny defect 低於 token 有效尺度；取像條件變動或缺件關係也可能不被 token residual 表達。

正確下一步：驗 effective pixels、acquisition state 和適合的結構方法；條件不成立先 HOLD。

工程第一步

POC 第一件事：證明模型不是在抄 token
固定 foundation checkpoint/layers、ROI/feature recipe、class roster/balance、decoder architecture、noise/dropout、linear attention、loose loss、seed 和 checkpoint。
鎖 token residual、layer fusion、resize、aggregation、calibration、threshold 和 per-class candidate evidence。
以 controls ablation、real challenge/future/drift split 報告 per-class escape、false reject/review load、tiny defect、P95、adaptation cost 和 seed spread。
目前做法

固定 Foundation checkpoint/layers、multi-class roster、normal balance、anti-copy controls、decoder/loss、token fusion 與每類 calibration。

要量什麼

逐類量 escape、false reject、review load、tiny-defect evidence、seed spread、controls ablation、adaptation cost 與完整 P95。

反例測試

移除或弱化 dropout／Linear Attention／Loose Reconstruction，或留出 rare class，確認 identity shortcut 與 pooled metric 如何掩蓋 per-class escape。

誰確認

各產品類別製程 owner、Vision ML owner、shared-model governance owner

先停下來的訊號：anti-copy state未鎖、類別coverage不平衡、support受污染、domain mismatch、tiny defect/global logic或完整P95未驗時，先 HOLD。
