# 教學歸納、評分與迭代循環

目標：把回饋變成有證據的改進，並讓下一輪真正使用學到的原則。跨主題共用，不固定模型、八章結構、繪圖工具或專案路徑。

## 先辨識這次要做什麼

- 先判斷會話中是否仍有未完成的製作授權，再判斷最新一句是否只是評語。先前要求做到達標，而重評撤回達標結論時，原製作工作重新開啟；貼分數、詢問評分或要求記錄學習，不會自動把它縮成只討論。
- 「你覺得這個看法對嗎」只有在沒有上述未完成製作授權，或使用者明確要求「只評、不改」時，才作獨立審查並停在紀錄；不先承諾全盤接受。已有製作授權時，先回答判斷，再依成立的缺口繼續實作。
- 「把學習寫進 Markdown，再產生／下一輪／一直做到達標」：在已授權範圍內完成下面循環，不停在計畫或文件更新。
- 「建立／修改這個 skill」單獨出現：完成技能與相關記憶。若同時說「再下一輪／重製」，兩件事都要完成：先更新技能，接著實際重製當前教學，不以技能完成作為停止點。
- 若製作正在進行，途中問題預設是補充或修正，除非使用者明確要求暫停／只討論。保留已有授權和範圍。
- 即使上一個回覆已結束，仍檢查先前製作目標是否真正完成。使用者要求持續「評分→學習→重製」而作品仍未達標時，後續要求記錄學習或更新skill是製作的前置工作，不撤銷既有授權；完成文件後回到實際製作，不等使用者再次催促。只有明確縮小／暫停範圍才停在文件。

從目前專案、會話與檔案推斷主題、受眾、入口和上一輪版本。只問真正缺少且會改變工作的資訊。初次使用說明正在套用此技能。

## 接上持久記憶

先讀 AGENTS.md、現有 TODO／STATUS、目前評分量表、製作指南及共享 review log 的最新相關輪次。尋找檔案時先限於工作區與合理父目錄，避免掃整顆磁碟。

| 文件 | 唯一責任 |
|---|---|
| `TEACHING_SCORING_RUBRIC.md` | 分項、配分、證據、否決項與門檻 |
| `TEACHING_REVIEW_LOG.md` | 所有主題共用的輪次、回饋取捨、分數、證據、修正及待辦 |
| `TEACHING_WEBPAGE_GUIDE.md` | 跨主題可重用的教學、案例、選型、互動與閱讀原則 |
| `IMAGE_STYLE_GUIDE.md` | 跨主題可重用的圖像語意、連續性、視覺與證據標示原則 |
| 專案 TODO／STATUS | 當前進度、生成資產、驗證、阻礙及使用者審閱狀態 |

同一專案的各主題不要另建 review log。保留已有命名與唯一權威，不複製出第二套同名規則。技能是流程；專案 Markdown 是可演進的記憶。

使用者要求「把學習寫進 skill／指南」時，不能只追加進度或分數：依上表把成立的共用原則併入對應文件，跨專案的決策流程更新本技能或其參照；評分相關學習補證據判準，不為成品改配分。共用 log 記錄「觀察 → 規則位置 → 下次如何驗證」，並區分本機保存與已提交／發布。既有規則已涵蓋者補精確缺口，不逐輪複製整套條文。

若專案尚無量表，對本技能的「工作導向模型教學」受眾，可用 [references/default-rubric.md](references/default-rubric.md) 建立初版；有既存量表就以它為準。其他受眾應先依任務訂合適量表，不能套用不相干的模型比較配分。

在 visionAI 專案執行時，另讀 [references/visionai.md](references/visionai.md) 對接檔案與驗證入口。其他專案不需要讀這份參照。

## 頁面上每一個圖槽都要自己查

若使用者說網頁沒更新、還是小圖或舊附圖，先跑 `teaching-visual-slot-audit`（專案說明 `TEACHING_VISUAL_SLOT_AUDIT.md`）。必須自己截 `/interactive-learning.html` **和** `/docs/index.html`，並量 CSS 寬；只比 course 路徑 hash 會漏掉 docs 仍用 388px 機制 SVG 的情況。不要請使用者自己看完再回報。

## 影像製作與評分的必要入口

涉及教學影像的產生、重製、重評或產圖規則時，必讀 [references/image-production-cycle.md](references/image-production-cycle.md)。其中G0–G6定義：接續版本、實看參考與逐圖brief、工具選擇、單圖原型、成圖審查、分項評分、學習後再生成。只更新技能時把流程寫好並驗證；已要求下一輪製作時按流程實際產圖。

不可跳過的關係：**參考與圖像證據先於renderer；單圖原型先於批量；可見證據先於分數；學習寫回先於下輪生成。** 不承諾每次首稿高品質；用這些關卡阻止未達標成品被宣稱完成。量表仍以專案現有版本為準。

## 一輪的完成條件

1. **保存基準。** 記錄主題、目前啟用版本、圖像清單、量表版本與本輪任務。保存可恢復的來源或版本差異，不覆寫尚未整合的使用者改動。閱讀實際來源，別因檔名較新就執行會覆蓋內容的生成器。
2. **審查回饋。** 對每項回饋寫「採納／部分採納／不採納／待證據」及原因。分辨使用者明示偏好、技術事實、審閱者推測、可選加分項。高分不是反駁讀者的理由；單一評論也不是普遍規則。
3. **先寫回學習。** 在共用 log 記錄「觀察 → 原因 → 可重用原則 → 適用條件 → 下一輪驗證」。一般化原則寫入相應指南，個別模型參數或缺陷留在輪次紀錄。搜尋既有規則後合併或修正，避免每輪累積重複條文。這一步必須在重製之前完成。
4. **實際重製（製作循環的必要交付）。** 依採納項目修改真正的教學來源，重新產生受影響的圖像、頁面與所需本機產物，更新啟用引用，確認提供的入口確實載入新版本。保留有效結構，不固定加章、加題或全量重畫。記錄生成模式、設計／prompt 意圖、版本、保存路徑與是否真實推論。只有 Markdown、評語、分數或待辦改變不算重製；即使既有分數 >90，使用者要求下一輪且已有採納改善時也必須實作。若受阻，交代真正缺少的條件與未完成資產，不假稱完成。
5. **檢查實際成品。** 讀完整主線、看逐張啟用圖，測桌面／手機、圖像放大與邊緣可達性、導航、答案顯示。數值獨立核算、技術主張核對第一手來源。截图等載入與捲動穩定；構建或 DOM 檢查不能取代視覺檢查。未變動資產可引用可確認相同的既有證據，新布局與受影響內容必須新驗證。
6. **固定量表重評。** 每項附可定位證據、保留優點、扣分理由；各圖獨立列分項與總分。檢查加總及否決項。沒有看過的成品寫「未評估」，不能推測通過。分數不得因版本增加而自動提高。權重不在同一循環中為了達標改動；改量表需版本化並重評可比較基準。
7. **決定下一輪。** 未達門檻或存在實質缺陷，寫回原因與驗證方式後再重製；保留每輪成敗。交付前核對：已接受缺口、實際改動資產、啟用引用及新驗證是否對得上。已有製作授權且仍有可做項目時，「撤回分數＋寫TODO」只是checkpoint，不是最終交付。通過且完成當前已採納範圍後，交付可開啟的新版本、證據與剩餘限制。新回饋到來時從紀錄接續，不從頭重置。

每輪最少記錄：輪次 ID／日期、來源與啟用資產、量表版本、回饋取捨、頁面與各圖分項、證據路徑、否決項、學習寫回位置、實作與驗證結果、下一輪或停止原因。

## 評分時容易犯的錯

- **說得對不等於畫得清楚。** 先看成圖能說明什麼，再核對brief；不能用正文、自己的模型知識或預期答案替圖片補分。這是分段審查，不是假稱獨立盲評。
- **通過檢查不等於接近滿分。** 正確、可載入、無溢出與來源誠實只支持相應證據。先依量表等級逐項判斷，不从100只扣小錯；參考完整度、五項完成度亦需各自理由。
- **高分被指出有問題時要重開狀態。** 保留舊紀錄並標明被取代，重新檢視同版本；不能因完成門檻是90就把缺陷評成91。未一併校準的歷史版本不能當客觀進步曲線。

- **會用不代表懂模型。** 對此工作導向受眾，必要原理要能解釋角色、比較對象、結果來源、有效原因與限制。效率或其他主打優點需說來源和取捨，不能只提名稱／版本；避免退回逐層架構和公式堆疊。
- **同一案例要走到底。** 維持工件身分、位置、單位與數值，連接輸入、處理、結果、判斷與人的行動。圖中聲稱變化，就要讓人看見變化。
- **證據分層。** 示意圖教概念；數值例證明可追算；真實推論顯示模型行為；共同實測才支撐比較。成功圖片不代表準確率，原則上也看正常、誤報／漏檢及使用條件。缺乏實測可以交付誠實限定的教學，但不能說已完成使用者明確要求的實測。
- **比較要有判斷依據。** 同資料、輸出目的與成本條件下比較；跨論文／硬體數字不直接排名。資料量、記憶體、延遲和錯誤指標要交代測法與條件。
- **有題目不等於主動學習。** 優先使用有合理取捨的選項，要求依資料、時間、風險與輸出需求說明理由。基本誤解題可以保留，但不要全部是明顯錯誤對明顯正確，也不以固定頻率或題數加分。
- **能滑不代表好讀。** 同時評估操作可達與理解負擔。手機若需反覆左右對照，考慮直向流程或分段；加提示不是唯一修法。
- **自評不是驗收。** 分開列出實作完成、工具驗證、自評達標、真人學習證據、使用者核准。任何一項都不能自動替代另一項。

## 持續與停止

本受眾未另指定時，使用預設量表：整頁及每張啟用圖各自嚴格 >90，無否決項，五項視覺完成度各 >=8。不得用平均分遮蔽低分圖；數值達標仍需完成本輪已採納的實質要求。

不要為了省工作停在文件、計畫或第一版。也不要為了湊分無限改寫：相同問題連續兩轮沒有改善時，更換改善方法、重新檢查評分證據或取得缺少的資訊；有可做的獨立工作就繼續。缺工具、資料或外部條件時記錄具體阻礙與可續作步驟，不假造通過或把迭代上限當品質門檻。使用者明確停止／縮小範圍時遵循新指示。

本技能不增加外部發布、付費生成或大規模訓練授權；沿用當前會話已有授權，不每輪重問。完成後交付簡短結果：新版本入口、學習 Markdown、實際檢查、分數與未解決限制；只更新技能／文件時明確說網頁未重製。
