# 教學影像：產生、檢討、學習與重製

用途：教學圖的製作或重评；讀完專案指南與固定量表後使用。這份文件規定流程與證據，不另外訂一套配分、不固定模型或版型。只更新技能／規則時可交付文件；使用者要求下一輪製作時，必須真正生成並驗證新成品。

品質承諾是「每次都有可追查的檢查，未通過不當作完成」，不是保證生成工具每次首稿都優秀，也不是保證自評代表真人理解。

## G0：接續實際版本與規則

1. 找出目前啟用圖、來源、使用者最新回饋與共用紀錄。歷史高分、檔名版本或測試通過不能代替當前狀態。
2. 讀指南中的適用規則、優先順序、歷史撤銷與已確認參考。文件太長時分段閱讀，不把截斷輸出當作已讀完。新偏好與舊固定版型衝突時，依文件和使用者明示的優先順序處理。
3. 記錄量表版本、每圖責任及交付範圍。若重評後撤回高分，更新當前状态，保留歷史評分，不能繼續以舊高分標記達標。

產物：共用 log 裡的輪次、基線／資產清單、有效規則和本輪問題。不要另開各主題 review log。

## G1：先看參考，再写視覺因果 brief

先實際打開使用者指定或指南認可的參考圖，記錄檔案／投影片頁與可沿用的特徵，例如證據區比例、差異放大、閱讀路徑。不能只列檔名，或將未獲认可的前一輪圖稱作母版。缺少指定參考時先找現有位置；找不到則記錄缺口，不聲稱已比對。沒有指定母版的專案可由教學任務建立候選，標示尚未驗證。

每張圖繪製前，將下表填入共用 log 或既有製作 brief，並從 log 連過去：

| 欄位 | 要填的內容 |
|---|---|
| 核心理解 | 讀者應能復述的一句因果／取捨，不只是名詞清單 |
| 工作問題 | 具體物件、困擾、這張圖負責的範圍 |
| 輸入與身分 | 同工件ID、方向、缺陷位置；哪些條件保持不變 |
| 方法與改變 | 模型／人做了什麼；哪些變數真的改變 |
| 可見證據 | 每項主張靠哪個局部、對照、結果或流程差異支持 |
| 下一步 | 看哪裡、代表什麼、接著採取什麼動作 |
| 構圖與參考 | 解釋、前後對照、比較、局部放大等；選擇理由與實看參考 |
| 關係 | 主箭頭起點、終點與語意；對應／放大不要冒充因果 |
| 證據等級 | 示意、可追算例、作者輸出或本機實測；來源與能支持的範圍 |
| 文字與數字 | 必要短標籤、正文移出項、數字是否幫助判斷及其來源 |
| 這輪修正 | 上輪缺點、採用哪條學習、這次看什麼才算改善 |
| 生成與驗證 | 工具／模式、預計路徑、實際呈現尺寸、需檢查的風險 |

必須能把「主張 → 圖上證據」一一對應。若核心解釋只能放一段文字，先改構圖：補真實局部、匹配對照或作業過程，不用裝飾工件替代方法。

一張圖只承擔已宣告的核心問題；比較圖可選「誰產生分數」「準備什麼資料」等共同維度，不必重播每個方法的完整架構。簡化時仍保留支持比較的必要路徑；共同输入不代表同一模型或輸出匯流。區分原始輸入、外部參考、模型估計與訓練真值，箭頭說明起終點及資料／條件／監督用途，避免把估計畫成已知答案。

## G2：依教學責任選製作方式

- 需要可信工作場景、材質、工件細節或半立體插畫時，可選影像生成，依可用工具與其技能操作，並提供已看過的參考。生成圖一律不冒充模型實測。
- 精確箭頭、圖表、數字、標籤或可重現幾何可用SVG／HTML等；也可將影像主體與精確標註組合。不能因程式容易複製就固定三欄版型。
- 作者圖／實測圖保留出處與身分；裁切、放大和強調不得改變證據意義。生成器不得「美化」出不存在的缺陷、熱區或結果。
- 工具不直接決定分數；重點是成圖是否符合專案風格並解釋工作問題。不為追求寫實而堆無關設備、人物或裝飾。

### 可重用的生成指令結構

將G1實際內容代入；程式繪圖同樣以此作設計規格：

```text
受眾及唯一學習目的：〔G1核心理解與工作問題〕。
參考圖：〔已檢視的來源〕；沿用〔構圖／質感／層級〕，不照抄不相關內容。
主體與連續性：〔工件、位置、方向、保持條件〕。
視覺故事：〔輸入〕→〔具體操作／比較〕→〔可見結果〕→〔接手動作〕。
每一步的證據：〔主張與對應局部／圖表／工作畫面〕。
必須看得出的差異：〔改變前後及對齊方式〕。
短標籤、色彩與圖例：〔逐字文字、色彩語意、必要數字〕。
證據身分：〔示意／引用／實測〕；不得暗示〔尚未支持的結論〕。
本輪修正：〔上輪失敗點〕；改善的可觀察條件是〔驗證方式〕。
避免：文字框冒充核心機制、重複工件填空、無意義箭頭、無依據效果排名。
輸出：〔尺寸、格式、輸出路徑／版本〕。
```

不要求純圖無字；文字應指引觀察、命名必要角色、解释判斷，不能承擔全部方法差異。

## G3：單張原型通過後才擴展

新風格、主要構圖變更或舊版已被指出無效時，先選一張能暴露主要風險的代表圖製作。先按G4/G5檢視與評分，再決定是否沿用到其餘圖。不要先批量複製，才發現整組都只是文字卡。

- 原型未過：先寫回原因與具體改法，再重製該圖；不要以換字、換色或增版本號當改善。
- 原型過關：代表構圖可繼續試用，不代表其他圖自動通過，也不代表使用者已批准。
- 每張新增圖仍需自己的G1與逐圖檢查。既有已驗證、未變動的圖不用為湊輪次重畫。
- 沿用會話授權自主修正，不另增逐圖許可流程。若確有尚未滿足的使用者審閱要求，交付具體原型並清楚區分自評與核准。

## G4：先評實圖，再回到正文

審查時先看最終圖與必要標籤，先不看作者brief、舊分數或希望讀者理解的答案；寫下實際可見的內容與缺口，再核對原目的。此為同一審閱者的分段審查，不冒稱獨立盲評。

| 檢查 | 可接受證據 | 常見假通過 |
|---|---|---|
| 故事 | 可辨識物件、操作、結果及下一步 | 看懂標題就說整圖懂了 |
| 因果 | 箭頭與位置可追蹤，知道何物改變 | 重複圖加箭頭但沒有轉換 |
| 比較 | 同條件下可见方法、成本或工作差異 | 同一熱圖貼三次，只換模型名稱 |
| 局部證據 | 裁切有來源定位、相同位置及倍率 | 幾乎相同空白塊配不同分數 |
| 主線深度 | 必要原理能解釋用途和限制 | 術語齊全，方法只剩文字框 |
| 風格 | 對照實際參考，主體與資訊密度支援教學 | 白底藍框、整齊就當高品質 |
| 判讀 | 圖例、熱區與處置有連結 | 一張漂亮熱圖直接算好教學 |
| 實際閱讀 | 目標頁面尺寸可辨識，手機對照不失上下文 | 只有原圖100%可讀或只驗DOM |

遮住長說明後再看是找出文字依賴的方法，不要求移除所有標籤，也不宣稱完成真人理解試驗。

檢查完整實圖、局部放大、頁面內縮放與手機；數字另核算、主張查原始來源。保存成品路徑與截图，使用版本或hash確認證據對應的資產。自動檢查只報它真正能驗證的範圍。

生成式編修的「其他不變」只是意圖：每次成圖重新檢查全圖的重複工件、正常／缺陷身分、位置、特徵對照、箭頭及頁尾，不能只看要求修改的局部。若兩輪微型格或紋理仍混淆，依G6更換呈現法，例如刪除冗餘縮圖、放大主要對照或使用明示的乾淨示意；不刪掉唯一的核心證據，也不以生成圖替換實測證據。

手機版須重排區內資料流，不只把外層區塊直向堆疊。記錄實際內容寬度並在該寬度審讀，檢查配對能否追蹤、必要文字及結論是否完整。整圖可放大只支持可達性；若主要理解必須反覆放大或跨區尋找，仍屬閱讀負擔。

## G5：用固定量表，防止分數膨脹

1. 對每分項先列可見證據，再依既定等級給分並加總；不要從100只扣小瑕疵。若有實質缺口，就依該量表的缺口等級，不因「文字寫到了」給接近滿分。
2. 圖片分數不能借正文、製作意圖或審閱者專業知識補足；完整網頁另評。技術正確性、來源誠實與介面可用，不自動提高案例、方法意義和圖像閱讀分數。
3. 完成度各項也要有理由：美感看構圖與參考；完整看責任是否完成；專業看物件和證據可信；密度看有用證據而非字數；層級看觀察路徑。不要整列複製8或9。
4. 每圖至少記保留優點、實質缺口、分項證據與總分；否決項另列。只有技術通過但故事未過時，維持「需重製」。
5. 使用者質疑高分時，重新檢視同一版本，標明舊分數被取代及原因。量表未變但評分校準改變，也不要把不同校準下的版本分數畫成進步曲線。
6. 90以上不能只靠數字：當前已採納的實質缺口仍在，就不能交付為完成。依專案門檻驗每張，不用平均分抵銷失敗圖。

評分記錄須指出所看的是原生圖、頁內桌面圖、頁內手機圖或整頁，並列未審範圍。共用同一圖片可沿用已確認相同位元內容的圖像證據；不同頁面標題、圖說、順序與顯示尺寸仍各自驗證。載入次數、hash一致或檔案數量不增加教學分數；小字限制按是否妨礙該圖核心理解評判，不能固定只扣一分。

沒有共同實測時，模型比較可用有來源的「資料準備／查庫／訓練／換產品／人工操作」差異。不捏造熱圖差異或性能排名，也不因沒有實測而否定所有概念圖。

## G6：學習必須改變下一張成圖

每個重要缺點用下表形成閉環，填在同一共用 log：

| 欄位 | 寫法 |
|---|---|
| 觀察 | 指出圖號、區域與可見問題，不只說不好看 |
| 原因 | 設計或審查哪個決策造成問題 |
| 共用原則 | 搜尋既有條文後修訂；能跨主題使用的才進指南 |
| 適用條件 | 什麼任務適用；避免將單次失敗寫成通用禁令 |
| 下輪變更 | 具體改構圖、素材、證據、局部映射或閱讀順序 |
| 驗證 | 下輪在成圖哪裡可看見修正；不要以高分本身作證據 |
| 結果 | 已修正／部分改善／未改善，附新路徑及缺口 |

先寫學習，再產生下一版；下一版brief要連回本次缺點。共用規則不重複累加，同類問題先修既有條文；個別數值、模型參數和失敗截圖留在log。

连续兩輪同一問題沒有實質改善時，更換構圖、參考或製作方法；不要繼續複製同一模板再調分。授權製作中仍有可行工作就繼續，確有工具／資料阻礙則保留未完成狀態與可續作資訊。不得為截止或迭代次數宣布合格。

## 輪次交付紀錄

在共用log保留：範圍／基線、規則版本、參考與brief、逐圖生成方式與來源、實際成圖證據、分項／完成度／否決項、修正與下輪驗證、目前啟用版本、未解決事項，以及下列分開的狀態：

- 已生成。
- 技術／介面驗證通過。
- 視覺與教學自評通過或需重製。
- 真人學習證據（沒有就寫沒有）。
- 使用者審閱／核准（不由自評推定）。

技能更新完成不會自動改變舊作品的狀態；聲稱下一輪完成之前，必須確認實際新圖與網頁引用已更新。
