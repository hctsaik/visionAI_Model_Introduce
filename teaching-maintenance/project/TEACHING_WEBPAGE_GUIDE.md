# 可重用教學網頁品質與改善指南

### WI-025：目前使用者認可的視覺參考

教學圖首選「共同幾何契約」「從對位到量測」，次選本輪貼出的 UniAD、DiffusionAD、WinCLIP、AnomalyCLIP；精確參考與使用方式以 [圖片指南第 11.3 節](IMAGE_STYLE_GUIDE.md#113-規則優先順序) 為唯一權威。設計頁面時維持具體圖像與清楚閱讀路徑，讓圖片有足夠顯示空間；手機版另行重排。此排序只確認視覺偏好，不代表內容或全頁驗收，亦不固定所有課的欄數。

### RULE-010：優點來源、真實取捨與閱讀負擔（2026-09-05）

模型的主打優點必須解釋來源與使用條件，提到輕量網路或版本名稱不等於講清效率。情境題應逐步加入兩個都有理由的選項，讓讀者依資料、時間、漏檢及覆核成本取捨；不能用題數或明顯正誤題宣稱已證明主動學習。

實際案例最好同時看正常品、成功異常及誤報／漏檢，說明模型與資料條件；單張成功熱圖不能证明準確率。手機既要能操作，也要容易理解；反覆橫向對照造成負擔時，評估直向或分段流程，而不是只加滑動提示。以上是改善判準，不表示已完成實測或手機重排。

### RULE-009：實用不等於可以省略機制（2026-09-05）

以讀者能說明「各角色做什麼、比較誰與誰、為何可能留下異常訊號」作為必要原理的深度標準；先補強既有核心章，不以增加章數、術語或公式取代解釋。同一案例要連續走過輸入、分支輸出、合成結果、決策依據與人的處置。

簡化數值只能證明流程可追算，不能當真實模型效能證據。真實輸出、論文基準與現場驗證分開標示。沒有共同實測時，模型比較交代資料量、硬體、設定、記憶體、完整時間與錯誤成本的測試條件，不拼湊排名。情境題放在需要做決定的位置，不固定每幾章湊一題。

目前評分統一採 [TEACHING_SCORING_RUBRIC.md](TEACHING_SCORING_RUBRIC.md) v1.0；以下舊配分保留歷史，不與新量表並行。

RULE-008（2026-09-05）：用案例教「變化」時，要讓讀者在圖中看見變化，再解釋其工作意義。換情境自測應改變工作條件或物件，並保持輸入、輸出身分連貫；不能只改標籤。

版本：0.3｜日期：2026-09-05｜受眾定位依使用者最新指示更新；成品另記審閱狀態

## 1. 目的與適用範圍

### 優先定位：工作導向的模型理解與選型（使用者確認）

目標讀者需要理解模型的意義、連結實際工作，並知道不同模型的優缺點；不以研究、推導或重新實作模型為學習目標。以下定位優先於本指南中容易被解讀為「完整展開架構與數學」的通用條款。

教完後，讀者應能說出：我的工作問題是什麼、這個模型用什麼線索判斷、需要我準備什麼、會交出什麼結果、結果如何幫助下一步，以及相較替代方法為何值得選它。單純將公式換成插圖，若仍在解說讀者不需要的內部細節，也不算對準受眾。

### 建議的主線內容

下表是每個主題要回答的問題，不是固定六張圖或六個章節。

| 讀者問題 | 要呈現的內容 | 適合的畫面 |
|---|---|---|
| 我的工作何時會遇到它？ | 一個具體困擾、現行做法及其缺口 | 實際物件／畫面與被圈出的問題 |
| 它憑什麼判斷？ | 一句白話直覺，加上造成能力差異的必要機制 | 同一案例的輸入、主要轉換與可觀察輸出 |
| 我會拿到什麼？ | 結果實際長相、如何判讀、能支持哪些下一步 | 原圖與結果對照，直接指出有用訊息 |
| 怎麼接進工作？ | 資料準備、是否需標註／訓練、輸入條件、誰使用結果 | 資料→模型→結果→工作動作，少量具體交接 |
| 什麼情況好用，什麼情況吃力？ | 一個成功條件與一個有解釋力的反例，附代價 | 同條件的成功／失敗對照及原因 |
| 為何選它而不是別的方法？ | 對同一工作需求比較輸出、資料、人力、速度與維護 | 對齊條件與結果的比較圖，結尾給有條件的選擇理由 |

### 內容取捨規則

- **主線保留**：用途、判斷直覺、必要機制、輸入與輸出、資料準備、常見失敗、替代方法、工作成本及下一步。
- **只在影響判斷時保留**：解析度、速度、資料量或性能數字；先說它對工作意味著什麼，再給有來源與條件的數據。
- **預設不占主線**：loss 推導、分位數運算、張量尺寸、逐層架構、論文消融表及實作 API。只有讀者確有進一步用途時才放進獨立技術參考，不因手邊已有內容就必須展示。
- **用問題決定深度**：某個術語或步驟若不會改變讀者對用途、輸出、選型、資料準備或失敗原因的理解，可刪除。必要機制仍須講清楚，避免變成只有「快、準、好用」的宣傳。
- **工程限制就近說明**：先讓人看見能完成的工作，再用具體反例解釋限制；不讓重複的 HOLD／REVIEW、設定清單與警語佔滿教材。

### 跨模型比較的共同欄位

比較先固定同一工作問題，選最相關的少數替代方法，必要時納入人工或傳統規則。各方法比較「交付結果、所需資料與標註、擅長情況、困難情況、運算與維護成本、何時優先考慮」。不要把不同輸出任務或不同測試條件的分數排成無條件排行榜。

每項優缺點採「條件→能力／代價→工作影響」寫法。例如不要只寫「資料需求低」，要說明少的是哪種資料、仍需準備什麼，以及對工作量的影響。對不能直接替代的模型，先說明任務差異，再討論是否能互補。

### 自測與品質判定

改用工作情境題：給讀者一個新需求，請他選候選方法、說出要準備的資料、預期結果與一個失敗風險。不要把計算結果、術語背誦或網路層數當成主要學習成果。

本次新增受眾適配檢查：讀者能否用頁面內容回答「它怎麼幫我的工作」和「什麼條件下我會選另一種方法」？缺少其中一項，不得僅憑技術正確與排版合格宣布 >90 分。原分項權重暫不改動，但舊版評分沒有涵蓋這次明確的受眾要求，需重新審查，不能自動沿用。

受眾與學習目標是使用者已確認的需求；上述具體教學順序和版面選擇仍是製作建議，需要透過代表頁和讀者回饋驗證，不能聲稱已證明整個受眾都喜歡。

所有主題的版本、評分、改善與學習集中在唯一的 [TEACHING_REVIEW_LOG.md](TEACHING_REVIEW_LOG.md)。不另建各主題的同名紀錄。

讓讀者看完教學後，能解釋「問題是什麼、方法如何改變輸入、結果從哪裡來，以及何時適合使用」。適用於模型介紹、演算法、工具操作、工程流程與其他技術教學網頁。

本指南從既有教學頁的問題歸納可重用的改善方法。共用的是提問方式、證據標準與驗收方法；每個主題仍須依自身機制撰寫內容。

搭配 [IMAGE_STYLE_GUIDE.md](IMAGE_STYLE_GUIDE.md) 使用：該檔指導單張圖的生成與視覺品質，本檔補充整頁閱讀順序、跨圖連續性、內容深度、互動與學習驗證。圖片風格依原指南目前適用條款，尤其第 11.11 節的最新偏好；不要抽取早期固定欄數或 C／D 限制，當成所有內容都必須套用的結構。

本次依據既有評估紀錄、保存的桌面截圖與頁面文字整理，未重新執行全站或手機測試。下列共用建議是評審判斷，尚不代表使用者核准，也不代表所有教學頁都有相同問題。

## 2. 從現有問題提煉的改善方向

既有頁面已具備白話入口、進階內容折疊、明確能力限制與查閱入口，這些應保留。優先改善的是讀者從摘要走向理解時的斷層。

| 已觀察到的問題類型 | 對學習的影響 | 可共用的改善原則 | 可檢查的完成證據 |
|---|---|---|---|
| 頁首、導讀卡與圖前說明重複用途、輸出及停止條件 | 捲動增加，理解沒有前進 | 每區新增一個解釋、例子、比較或推導；合併功能相同的摘要 | 能為每區寫出「本區新增了什麼」 |
| 工程參考／摺疊區重貼第一遍同一張圖 | 多一次點擊卻沒有新觀察 | 第一遍出現過的 PNG 不得再嵌入；工程參考只留設定核對文字 | 展開後沒有與 beginner 相同的 `src` |
| 開頭有白話摘要，關鍵機制仍跳步 | 記得用途，說不出如何做到 | 將核心轉換展開為可追蹤的輸入、動作、中間結果與原因 | 讀者可用自己的話解釋一個中間步驟 |
| 把算法課當成異常偵測模型來寫 | 讀者以為有權重、有正常品庫 | 開場先說是算法還是學習模型；「如何做」畫真正的步驟 | 遮住正文仍能說出有沒有訓練、線索是什麼 |
| 通用小標與下方圖片回答不同問題 | 讀者依錯誤提示看圖 | 標題、圖、圖說、自測共同回答同一個問題；不得只依圖的序號套上「結果／停止／比較」 | 在實際頁面逐槽核對四者能否對應同一句學習目標；更換首圖後也重查後續槽位（WI-019） |
| 聲稱同一案例，前後圖卻換成不同外觀物件 | 無法追蹤變化究竟來自方法或換了樣本 | 保持案例身分、區域與量尺連續；換案例須明示 | 原圖、處理圖、結果能逐一對回 |
| 呈現結果與名詞，缺少具體推導 | 結論只能背誦，無法核對 | 提供至少一個完整工作例，展示必要中間證據 | 從結論可反查到輸入與處理過程 |
| 為了白話而把指標定義寫成不精確口訣 | 容易形成錯誤概念 | 白話解釋保留方向、條件與適用範圍；正式定義就近可查 | 定義與例子沒有互相矛盾 |
| 限制與停止條件比運作原理更醒目 | 知道要小心，卻不懂方法本身 | 先建立基本能力與機制，再把必要限制放在對應判斷點 | 讀者同時能說出何時有效、何時失效及原因 |
| 檢查偏重檔案、字級與版型是否合格 | 技術檢查通過仍可能教不懂 | 分開檢查內容、成圖、實際頁面與學習表現 | 每類檢查都有獨立紀錄 |

網站各層「誰讀、新回答什麼、能否重圖」見課程 [`TEACHING_SITE_READING_LAYERS.md`](teaching-images/vision-ai-model-selection/TEACHING_SITE_READING_LAYERS.md)。幾何課（SIFT／ECC／ChArUco）與學習配對器（LightGlue）的分界見該檔「方法還是模型」。

以上是抽樣觀察的歸納；手機可用性、鍵盤操作及其他主題的缺陷，應實測後另記。

## 3. 先定義讀者最後要能做什麼

開始撰寫前填入：

- **受眾與先備知識**：讀者已懂什麼？首次接觸什麼？
- **核心問題**：讀者帶著哪一個問題進來？
- **可觀察的學習成果**：讀完能解釋、比較、預測或操作什麼？
- **回答範圍**：本頁回答到哪裡？哪些需要下一課或外部資料？

學習目標用「能沿例子說明結果如何產生」或「能根據兩個條件選擇方法」，避免只寫「理解某技術」。

初學者頁優先建立機制；工程實作頁增加設定與驗證細節；決策摘要頁聚焦問題、證據與行動。先選受眾，再決定資訊深度。

## 4. 讓閱讀持續前進

以下是內容責任，可合併或拆分，不要求固定章數、卡數或圖片數。

| 內容責任 | 讀者的問題 | 建議呈現 |
|---|---|---|
| 建立情境 | 為什麼需要這個方法？ | 一個具體問題與預期產出 |
| 看見全貌 | 整體如何運作？ | 可追蹤的完整案例或總覽 |
| 理解關鍵 | 哪一步產生差異？為什麼？ | 必要中間結果與機制解釋 |
| 解讀結果 | 結果代表什麼？ | 同案例的結果、量尺、計算或操作回饋 |
| 判斷適用性 | 條件改變會怎樣？ | 受控比較、反例與能力邊界 |
| 驗證理解 | 我能自己解釋或使用嗎？ | 預測、判讀或遷移題與解答理由 |

需要操作前先知悉的前提，放在操作之前；其他限制就近附在相關步驟，避免每一區重複完整警語。

頁首簡短交代用途與學習路徑，盡早出現核心圖或實例。每次新增區塊前先問：它補上哪一個尚未回答的問題？若只是換句話重述前文，合併或刪除。

## 5. 共用骨架，保留主題特有的機制

每個核心步驟交代四件事：接收什麼、做什麼、產生什麼、為何需要它。

「處理資料 → 分析 → 得到結果」通常不足以解釋方法；應把動作寫到足以區分其他方法的程度。專有名詞第一次出現時，用短句解釋它在當前步驟的角色。

對模型、系統或工具，明確區分原生輸出、後續處理與人為判定。若建立／訓練階段和使用／推論階段不同，分開標示；若方法具有並行、回饋或分支，就保留真實關係，不為整齊而改畫成直線。

**替換名稱測試**：把主題名稱換成另一種方法後，整段內容若仍完全成立，檢查是否只剩通用背景。背景可以共用，核心機制必須說出該方法的差異。

## 6. 用一個可核對的例子完成解釋

一個完整工作例應包含：原始問題、必要中間狀態、可觀察結果、結果解讀與下一步。

- 跨圖追蹤同一樣本時，保留身分、幾何、區域、方向與必要標記；裁切或縮放標出對應範圍。
- 比較方法時固定共同條件、案例與結果尺度，明示正在改變的因素。
- 定量主題展示輸入數值、具名運算與結果；定性或操作主題可用狀態變化、操作回饋或可觀察差異，不必硬加數字。
- 示意資料、生成式影像與真實實驗結果分別標示。示意數字用於解釋流程，不能充當方法效能證據。
- 圖中每個分數、標籤或顏色，都應有對應的資料或圖例。結論的強度不得超過證據能支持的範圍。

**反向追溯測試**：指著結果，能否依頁面內容回答「它來自哪個輸入？經過哪些必要轉換？哪個條件支持這個解讀？」

分段後也執行同一測試：必要的來源或位置錨點應在當前視圖可見，不能只把流程改寫成數條短句。精細算術可選讀，但主線須看得出中間結果如何支持下一步；以實際手機頁面檢查，不用原圖放大代替。（A10，既有追溯原則的檢查補充。）

## 7. 圖文各有工作，並且互相對得上

| 元件 | 主要責任 |
|---|---|
| 標題 | 提出本段真正要回答的問題 |
| 主圖 | 展示物件、關係、變化與證據 |
| 圖說 | 指出該看哪裡，以及差異代表什麼 |
| 進階說明 | 補充推導、設定、精確定義與來源 |
| 結論 | 回答本段問題，必要時附上成立條件 |

避免標題、卡片、圖說與結論逐字重複。必要的重複應服務比較或記憶，並有明確用途。

圖片遵循 `IMAGE_STYLE_GUIDE.md` 的因果、證據與視覺層級原則。流程、比較、時間變化、空間關係、矩陣與分布，依內容關係選擇結構；不要將所有課題都畫成相同流程卡。

先保留已成立的主結構，針對缺少的證據或解釋局部補強。只有主結構造成理解障礙時，才考慮更換版型。

## 8. 網頁本身應幫助學習

下列是後續製作與測試準則，本次未逐項實測。

- **預設可見內容能獨立教懂主線**：讀者不必展開多處隱藏區域才能接起基本因果。
- **展開項目說明價值**：例如「查看計算過程」或「比較兩種設定」，讓讀者知道點開會得到什麼。
- **導覽清楚**：顯示目前章節與相鄰章節；返回後能找到原先閱讀的位置。
- **圖片可讀**：以實際桌面及手機寬度檢視，必要時提供放大；關鍵解釋不能只存在於縮得太小的圖中文字。
- **基本可及性**：圖片有適當文字替代或鄰近完整解釋；重點不只靠顏色；控制項可用鍵盤操作且焦點可見。
- **互動產生理解**：改變一個條件時，讓結果和原因一起更新；單純切換裝飾或累積進度不算教學回饋。
- **完成標記與理解證據分開**：讀者勾選完成表示進度，自測表現才提供理解程度的線索。

## 9. 自測要能揭露誤解

依學習目標選擇適合的題型，不要求每課全部使用：

| 題型 | 通用提問模板 | 解答應包含 |
|---|---|---|
| 復述 | 這個輸出是如何從輸入產生的？ | 必要步驟及其關係 |
| 預測 | 只改變這個條件，哪個結果可能先改變？ | 預測與機制理由 |
| 判讀 | 這兩個結果支持哪些結論？ | 證據、限制與常見誤判 |
| 遷移 | 換成新情境，哪些前提還要重新確認？ | 適用條件與判斷過程 |

至少有一道題需要使用本頁的核心機制或證據。解答說明為什麼，並指出常見錯誤推理，避免只給正確選項。

## 10. 建議審查流程與優先順序

1. **核對內容**：核心問題、術語、案例身分、數字、因果與結論是否一致。
2. **追蹤閱讀**：逐段寫出新增知識，修補跳步，合併重複摘要。
3. **核對成圖**：檢視實際輸出，不以提示詞、原始碼或圖片尺寸推定內容正確。
4. **檢查頁面**：桌面、手機、展開內容、放大與導覽；記錄實測範圍。
5. **驗證理解**：請目標讀者復述或解題；沒有讀者測試時，明示只是評審預估。

修正順序建議：

- **P0：避免教錯**——內容矛盾、案例對不上、數值無來源、錯誤因果或結論超出證據。
- **P1：讓主線教得懂**——機制跳步、缺少完整案例、圖文不符、主要內容無法閱讀。
- **P2：讓學習更順暢**——重複摘要、導覽與分層、互動回饋、次要視覺調整。

優先級依實際影響調整；例如導覽故障阻斷閱讀時應提升優先級。先完成一個具代表性的段落，確認改善確實回答學習問題，再評估擴展到其他主題。

WI-009 D01跨題學習：講解訓練專用設計時，主線必須同時畫出不含真值的正式推論路徑；移除訓練設計的反事實只解釋少了何種學習訊號，性能影響另需受控重訓。提示的來源、模型交出的框或mask、人的品質判斷是三種不同問題；免提示不等於沒有詞彙或預訓練限制。比較圖優先畫出資料／監督／表示的不同流向，禁止用同圖加三段模型名稱冒充差異。
